# Phase 9 夏季排房 — 现场验收清单

在 **https://wulingkt.net**（或当前正式 Pages 域名）执行。每项打勾并记录执行人、日期、备注。

**目标：** 验证 9.1–9.5.2 完整业务路径可用，且远程多人看到同一份数据。

**建议环境：**

| 角色 | 账号建议 | 用途 |
|------|----------|------|
| 排房负责人 | `admin` 或带 `settings.write` 的账号 | 预分房、发布、打印 |
| 知客师 A | `zhike`（设备 1） | 待入住清单办理 |
| 知客师 B | 另一 `zhike`（设备 2 / 无痕窗口） | 多端同步观察 |

**测试营期：** 建议新建「验收测试营期」（勿用正式法会数据），含 3–5 名在住 + 2 名预约成员，性别/身份标签各异。

**入口路径：** 基础设置 → 营期管理 → 营期卡片 → **预分房**；房态看板可展开 **容量预测** 面板。

---

## 5. Phase 9.5 — 发布与待入住清单

### 5.1 发布

- [ ] 方案「已确认」且零硬性冲突时，出现 **发布待入住清单**
- [ ] 发布后进入待入住清单；**预计占位**人员不在清单中
- [ ] 发布后预分房草稿变为只读（显示「已发布」，不可再改编排表）
- [ ] 发布**未**自动写入 lodgers/reservations 床位（房态与发布前一致，除后续手动办理外）

### 5.2 逐条办理

- [ ] **按预分床办理** 一条在住挂单 → 房态该床变占用，清单变「已办理」
- [ ] **按预分床办理** 一条预约 → 转在住并占床，清单变「已办理」
- [ ] **跳过** 一条 → 状态「已跳过」，床位未被占用
- [ ] 办理失败场景（如床位已被占）：有明确提示，清单**不**误标「已办理」

### 5.3 重新发布

- [ ] **重新发布清单**（需 `settings.write`）后，「待办理」条目按当前草稿重建
- [ ] 已办理 / 已跳过记录**保留**

### 5.4 CSV 导出

- [ ] **签到表 CSV** 下载，Excel 打开中文正常
- [ ] **房间表 CSV** 按房间排序，字段完整

## 6. Phase 9.5.2 — 打印与复盘

### 6.1 浏览器打印

- [ ] **打印房间表** → 打印预览无横向溢出，营期名/日期/床位信息正确
- [ ] **打印门贴** → 按房间分组，姓名与床位对应
- [ ] **打印床位名牌** → 每人一卡，房间+床位+姓名正确

### 6.2 活动期调整记录

- [ ] 对已发布营期内在住人员 **换床** → 活动复盘页出现「换床」记录（原床→新床）
- [ ] 待入住清单 **跳过** 一条 → 复盘页出现「跳过预分」记录

### 6.3 活动复盘

- [ ] **活动复盘** 页：清单总数 / 已办理 / 已跳过 / 待办理 / 调整记录数正确
- [ ] **记录调整备注** 可写入一条「手动备注」
- [ ] **导出复盘 CSV** 含调整记录行

## 8. 权限抽查

| 操作 | 无权限账号应被拒绝 |
|------|-------------------|
| 发布 / 重新发布 | 无 `settings.write` → 权限不足 |
| 按预分床办理 / 跳过 | 无 `lodging.checkin` → 权限不足 |
| 查看清单 / 复盘 / 打印 | 无 `lodging.read` → 权限不足 |

- [ ] 至少抽测 1 项权限拦截（如 `viewer` 角色无法发布）
